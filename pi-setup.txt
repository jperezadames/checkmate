CheckMate — Raspberry Pi Setup
Things to install on the Pi before running the system.

Target: Raspberry Pi 5, Raspberry Pi OS (Bookworm or Trixie).


1. SYSTEM PACKAGES (apt)
   Not Python packages — installed with apt, not pip.

     sudo apt update
     sudo apt install stockfish

   - stockfish          Chess engine binary at /usr/games/stockfish
                        (the path config.json expects).
   - Chromium           Ships with Raspberry Pi OS; shows the UI on the screen.
   - python3-picamera2  Only for the Raspberry Pi camera module
                        ("backend": "picamera2" in config.json). The USB webcam
                        ("v4l2", the default) doesn't need it. It must come from
                        apt, which is why the venv below uses --system-site-packages.


2. PYTHON ENVIRONMENT
   Create the venv with --system-site-packages so Picamera2 stays visible
   (harmless when you use the USB webcam).

     python3 -m venv --system-site-packages .venv
     .venv/bin/pip install -r requirements.txt

   requirements.txt (runtime):
     python-chess   engine: board state + Stockfish interface
     numpy (<2)     camera math (pinned for Picamera2 compatibility)
     opencv-python  camera vision / ArUco detection
     pyserial       Pico USB link for LEDs, angle sensor, and Select
     fastapi        backend server
     uvicorn        runs the server

3. PICO AND SEEED GROVE SHIELD
   The Pi runs the website, camera, Stockfish, and game loop. A Pico on the
   Seeed Grove Shield handles the LED matrix and controls over one USB cable.

     Grove Button       -> shield D20 = Pico GP20 (HIGH when pressed)
     Grove Angle Sensor -> shield A0  = Pico GP26 / ADC0
     WS2812 matrix DIN  -> shield D16 = Pico GP16
     Screen and USB camera -> Raspberry Pi
     Pico USB -> Raspberry Pi USB (use a data cable)

   Set the shield's Grove voltage switch to 3.3 V so the angle sensor's
   output stays inside the Pico ADC's 0–3.3 V range. Power the 16x16 LED
   matrix from its external 5 V supply with a shared Pico ground. Route D16's
   signal through a 3.3 V to 5 V level shifter as needed by the matrix. The
   full matrix's power must come from that external supply, not the shield
   Grove power wire or USB. Keep the existing brightness cap at 50% or lower.

   Stop the backend and close Thonny before uploading firmware. Install
   MicroPython for your Pico model if needed (BOOTSEL + its UF2 file), then
   run from the repo root on the Pi:

     .venv/bin/pip install mpremote
     .venv/bin/mpremote connect auto fs cp checkmate/led/matrix.py :matrix.py
     .venv/bin/mpremote connect auto fs cp pico/main.py :main.py
     .venv/bin/mpremote connect auto reset

   Use an explicit port instead of 'auto' if other MicroPython boards are
   connected. Firmware details and the serial diagnostic are in pico/README.md.

   Give the backend user USB serial access once:

     sudo usermod -aG dialout "$USER"

   Log out and back in for the group change. Find the port with:

     ls /dev/serial/by-id/

   config.json's led.port matches the MicroPython USB device, with
   /dev/ttyACM0 as a fallback. Set led.port to the actual path if needed.
   Both LED commands and input polling use this one connection. Run one
   backend process so it is the sole serial-port owner.

   After firmware uploads, reinstall Python requirements in section 2.
   Changes to size / serpentine / rotation / mirror / max_brightness in the
   LED config are sent to the Pico on connection. Size is fixed at 16x16.
   The hard brightness cap in the firmware is 50%.

4. MIGRATING FROM THE PI GPIO DESIGN
   If the old service was installed, stop and disable it:

     sudo systemctl disable --now checkmate-rotary.service

   If systemctl says the unit does not exist, continue. Remove the previous
   CheckMate rotary-encoder and gpio-key overlay lines from
   /boot/firmware/config.txt. Disconnect the old Pi control and matrix-data
   wiring with power off, then use the Pico shield connections above.
   Reboot after editing the overlays. SPI can stay enabled for other devices.

   The angle sensor stops at each end. Its full sweep covers every enabled
   control on the current screen or dialog. Press the D20 button to activate
   the highlight. In move-history browsing, the knob sweeps through the list
   and Select returns to navigation. Keyboard Left/Right/Enter still work.
   If the knob moves the wrong way, change ROTARY_REVERSED in pico/main.py
   and upload that file again. BUTTON_ACTIVE is 1 for a standard Grove Button.
   Knob readings are smoothed; the UI holds focus near selection boundaries.

5. BUILD THE UI AND RUN
   Build on the Pi with Node.js >= 22.12 installed, from the repo root:

     cd ui
     npm ci
     npm run build
     cd ..

   Or build on a laptop and copy the complete ui/dist/ folder to the same
   location in the Pi checkout. Confirm ui/dist/index.html exists before
   starting the backend. The backend mounts the website at startup.

     .venv/bin/uvicorn checkmate.server:app --host 127.0.0.1 --port 8000

   Open http://127.0.0.1:8000 in Chromium on the Pi. First-run camera
   calibration and troubleshooting are in RUNNING.md. LED and controls are
   active with real LEDs, including CHECKMATE_FAKE=camera for board-free
   testing. CHECKMATE_FAKE=led or all also disables the physical Pico controls.

   To verify the controls without camera calibration, start with:

     CHECKMATE_FAKE=camera .venv/bin/uvicorn checkmate.server:app --host 127.0.0.1 --port 8000

   Open http://127.0.0.1:8000/?preview=1 and test color, difficulty, the flip
   button, and settings. Stop the backend before using mpremote or the
   standalone Pico diagnostic.

NOTES
   - requirements-dev.txt adds pytest and httpx for host tests.
   - No separate GPIO input service is needed. Pico controls go through USB,
     the backend, and the UI WebSocket. Keep Chromium on the game page.

     https://wiki.seeedstudio.com/Grove-Starter-Kit-for-Raspberry-Pi-Pico/
